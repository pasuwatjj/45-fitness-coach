45 Fitness Coach — คืนหน้าเว็บเดิม + แก้การเชื่อมต่อ v25

1. แตก ZIP แล้วเปิดโฟลเดอร์ 45Fitness-Restored-v25
   อัปโหลด “ไฟล์และโฟลเดอร์ข้างใน” ไปที่ราก GitHub repository เดิม
   app.py, Dockerfile, requirements.txt, static, templates และ models ต้องอยู่ระดับเดียวกัน
   รูปแบบที่ถูก: static/home.js และ templates/index.html
   อย่าอัปโหลดเป็น static/static/home.js หรือ 45Fitness-Restored-v25/app.py ใน repository
   ไม่ต้องนำ data หรือไฟล์ .db ขึ้น GitHub และไม่ต้องล้างดิสก์ Render

2. Render > Environment ตรวจว่ามี:
   FITNESS_PUBLIC_URL=https://four5-fitness-coach.onrender.com
   FITNESS_DATA_PATH=/data/fitness.db
   Render > Disks ต้อง Mount path /data (ดิสก์เดิม 1 GB)
   ใช้ Dockerfile เดิม: รัน python serve.py เพียงโปรเซสเดียว
   จากนั้น Manual Deploy > Deploy latest commit แล้วรอ Live

3. เปิด https://four5-fitness-coach.onrender.com/45-fitness-coach
   รีเฟรช Ctrl+Shift+R หนึ่งครั้ง
   หน้าแรกต้องมีหมวดออกกำลังกาย ปฏิทิน อันดับ สุขภาพ โปรไฟล์ และ VIP
   โปรไฟล์/กราฟ/คาร์ดิโอ/เพื่อน/แชต/รางวัล/ชาเลนจ์/หลังบ้านอยู่ครบจากไฟล์ต้นฉบับ
   หน้า VIP ใช้ QR เดิมและบัญชีกสิกรไทย 119-1-84148-0
   ถ้าไม่ได้ตั้งบริการตรวจสลิป จะส่งสลิปให้แอดมินตรวจเงินจริงก่อนเปิด VIP ตามระบบเดิม

4. เปิดสิทธิ์แอดมินให้บัญชีเจ้าของเว็บ:
   เข้าสู่ระบบด้วยบัญชีเดิม pasuwatoyasumi7@gmail.com ก่อน
   ถ้าระบบบอกอีเมลนี้สมัครแล้ว ให้เข้าสู่ระบบ ไม่ต้องสมัครซ้ำ
   Render > Shell รัน:

   แล้วรีเฟรชหน้าเว็บ ปุ่มหลังบ้านจะปรากฏสำหรับบัญชีนี้
   คำสั่งนี้ให้สิทธิ์เฉพาะบัญชีที่มีอยู่แล้ว ไม่มีการให้แอดมินอัตโนมัติตามชื่ออีเมล

5. ตรวจการจำบัญชี:
   สมัครบัญชีทดสอบด้วยอีเมลของคุณหนึ่งครั้ง แล้วลองสมัครอีเมลเดิม: ต้องถูกปฏิเสธ
   ปิด/เปิดแท็บ: ต้องยังเห็นอีเมลเดิม
   Deploy หรือ Restart service: ต้องยังเข้าสู่บัญชีเดิมและเห็นโปรไฟล์เดิม
   สามารถตรวจพาธและจำนวนบัญชีใน Render Shell โดยไม่แสดงรหัสผ่าน:

   python -c "import app; print('Database:', app.store.path); db=app.store.connect(); c=db.__enter__(); print('Accounts:', c.execute('SELECT COUNT(*) FROM accounts').fetchone()[0]); db.__exit__(None,None,None)"

สิ่งที่แก้:
- ต่อเซสชันใหม่อัตโนมัติเมื่อเซิร์ฟเวอร์เริ่มช้าหรือรีสตาร์ต แก้การค้างรอ /session ตลอดไป
- ต่ออายุเซสชันแล้วลองใหม่เฉพาะการอ่านข้อมูล ไม่ส่งคำสั่งสมัคร/ชำระเงิน/เริ่มเซตซ้ำ
- ตั้งเวลาหมดรอทั้งส่วนหัวและเนื้อหาผลกล้อง ไม่ค้างเมื่อเซิร์ฟเวอร์ตอบไม่ครบ
- เฟรมห่าง 2–10 วินาทีไม่ล้างการตั้งท่าเริ่มต้นทุกครั้ง แต่ยกเลิกครั้งที่ยกค้างเพื่อไม่ให้นับข้ามภาพที่หาย
- เว้นเฟรมเกิน 10 วินาทีจะให้ตั้งท่าใหม่ ต้องมีท่าเป็นกลางอย่างน้อย 3 ภาพ
- ลดการรีเซ็ตจากจุดร่างกายสั่นเล็กน้อยระหว่างเตรียม โดยยังปฏิเสธท่าเริ่มต้นที่ผิดเกณฑ์
- เปลี่ยนเวอร์ชัน URL ไฟล์ JS/CSS เป็น v25 และใช้รูปท่าเริ่มต้นที่อยู่ในเว็บทันที
- อีเมลถูกตัดช่องว่าง/แปลงตัวเล็กและบังคับไม่ซ้ำในฐานข้อมูลเดิม เพิ่มการตอบข้อผิดพลาดกรณีสมัครพร้อมกัน

ข้อจำกัดของการตรวจ:
ทดสอบการจำบัญชีจริงข้ามสองโปรเซสและการปฏิเสธอีเมลซ้ำแล้ว แต่ยังไม่พบต้นเหตุที่ทำให้อีเมลซ้ำได้บนบริการจริงตามที่รายงาน
ผ่านการจำลองเครือข่ายและท่าทาง ไม่ใช่การยืนยันความแม่นยำจากกล้องของผู้ใช้จริง
ภาพกล้องสดยังเล่นบนอุปกรณ์ แต่ผล AI ต้องเดินทางไปกลับเซิร์ฟเวอร์ Oregon จึงยังมีความหน่วงตามเครือข่าย
